# 新手指南 —— 从一条链接到指纹浏览器能用

目标读者：手里有 `vless://` / `hy2://` 节点链接，想让指纹浏览器的多个 Profile 各走一个固定出口，不想手写 YAML。

完成全程约 5 分钟。读完你会得到：

- 节点进了 Clash 的 `proxies`
- 一个（或几个）策略组作为「出口」
- 每个 Profile 一个本机端口，浏览器填 `socks5://127.0.0.1:端口`

---

## 第 0 步：启动

双击 `clash-profile-ui.exe`。它会自动：

1. 扫描 Clash Verge Rev 数据目录（`%APPDATA%\io.github.clash-verge-rev.clash-verge-rev`）
2. 加载最新的 profile 文件（自动跳过 `Merge.yaml` 这类覆写模板）
3. 打开浏览器进入 `http://127.0.0.1:18630`

顶部文件栏能看到已加载的文件路径 —— 确认显示的是你的 profile 名（一串随机字符那个 `.yaml`）。

> 没自动加载？把 CVR 安装/数据目录粘进「Clash 位置」框 → 点「扫描」→ 从下拉框选文件 →「加载」。

## 第 1 步：把节点加进来（任务①）

在「新手任务」第一块，把服务商给的链接**整行**粘进大输入框，点「解析」：

```
vless://aaaaaaaa-...@vless1.demo-example.com:31085?security=reality&pbk=...&sid=...#节点名
```

- 解析成功 → 下面出现待加入表，名称可以直接改
- 部分行失败 → 只有失败的行标红报错，成功的照常加入，不会卡死
- 一次可以粘多行，链接和 YAML 混粘也能识别

也可以粘**节点 YAML**（从别处复制的配置块），三种写法都认：

```yaml
- name: 我的节点
  type: vless
  server: 1.2.3.4
  ...
```

点「加入节点列表」→ 节点进入下方「已有节点」清单。

**核对节点对不对**：每行末尾的「详」按钮弹出该节点完整 YAML（uuid、密钥、flow 等全部字段）。和服务商给的链接逐字段对照 —— 这一步能发现 90% 的"连不上"问题（比如第三方转换器把 `sid` 写错）。

## 第 2 步：把节点组成「出口」（任务②）

组 = 给一批节点起个名字，端口绑组就能自动换节点。三种常用类型，界面上有大白话说明：

| 类型 | 什么时候用 |
|---|---|
| **url-test**（推荐） | 想让 Clash 自动测速用最快的、断了自动换别的 |
| **select** | 想自己在 CVR 代理页手动点选节点 |
| **fallback** | 按顺序用第一个能连的，挂了顺延 |

操作：输组名 → 选类型 → （自动类填测速 URL/间隔，默认即可）→ 勾选成员节点 → 「保存组」。

- 只绑单个节点不需要容灾的话，这步可以跳过，第 3 步直接绑节点
- 已有组可以点「载入」改成员再存回；删除被端口引用的组会在校验区报错

## 第 3 步：绑端口（任务③）

每个端口 = 一个本机代理出口。在表格里：

1. 「端口」填一个空闲端口（建议 12001 起顺序编）
2. 「出口绑到」下拉选节点或组
3. 第三列自动生成 `socks5://127.0.0.1:12001`，点复制

有几条记录就是几个独立出口，同时在线、互不干扰。

## 第 4 步：保存 + 让 CVR 生效

1. 顶部「YAML 预览」可以核对最终产出（可选）
2. 点「保存」→ 写回 profile 文件（原文件自动备份成 `.bak`）
3. **关键一步**：到 Clash Verge Rev 界面把当前 profile 切到别的再切回来（或重启 CVR）—— CVR 此时才重新生成运行时配置，改动才生效

## 第 5 步：指纹浏览器填代理

指纹浏览器 Profile 的代理设置里填：

```
类型: socks5    地址: 127.0.0.1    端口: 12001（你绑的端口）
```

每个 Profile 填不同的端口 = 每个 Profile 固定走不同出口。

---

## 出问题怎么办

| 现象 | 检查 |
|---|---|
| 保存后 CVR 里看不到新节点/端口 | 没切 profile —— 第 4 步第 3 小步 |
| 节点延迟测试 error/timeout | ① 「详」核对全字段 vs 服务商链接 ② 新版服务端要 `support-x25519mlkem768`（用工具粘链接会自动带上，第三方转换器常丢） ③ 服务端开 Vision 要 `flow: xtls-rprx-vision` |
| 端口 LISTEN 但浏览器不通 | 浏览器填的是 `http://` 代理？socks 类型端口只认 `socks5://`；要兼容就把该端口类型改 `mixed`（详细模式可改） |
| 组绑了但出口不通 | fallback/url-test 组内节点全挂 = 全不通；先让单个节点延迟测试过 |
| 校验区报错 | 红字 = 必须修（引用不存在/端口重复/组循环）；黄字 = 建议核对（如 Reality 参数可能不全） |

## 概念速查

- **listener（端口）**：本机开的代理口，浏览器连它；它的 `proxy` 字段决定流量走哪个节点/组
- **proxy-group（策略组）**：把若干节点打包起名，可自动切换/手动选/顺序备用
- **proxies（节点）**：上游代理服务器配置（vless/hy2 等），是流量的最终出口
- 链路：`浏览器 → 127.0.0.1:端口(listener) → 组/节点 → 目标网站`，**不走 rules 分流规则**
